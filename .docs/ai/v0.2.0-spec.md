# harness-deck v0.2.0 — design spec

_Status: draft. React inline; we commit once it's right, then build to it._

## Why this exists

Surfaced in product discovery (2026-05-26 / 2026-05-27):

1. **You use it constantly** — multiple times a day, primary surface.
2. **Six tabs is too many.** "I think there's just too many places to
   look for things — inbox, overview, latest, projects. We can simplify
   this: actionable stuff right now (inbox), long-term or strategic
   documents (projects). Put some fun metrics at the top of each."
3. **Pure-keyboard navigation isn't there.** "All of the above + I keep
   having to re-learn shortcuts." Bindings exist but don't compose.
4. **Audience stays small.** You + cowork + friends. Vim-fluent power
   users. Optimize for daily-use density, not stranger onboarding.

v0.2.0 treats these three threads as one cohesive rebuild.

## Audience & scope

**In scope:**
- Information-architecture collapse (6 views → 2)
- Operational metric strips at top of inbox + projects
- Vim-faithful, modal keyboard model with discoverable cheat sheet
- Settings/archive/latest/overview migrations

**Out of scope:**
- New manifest features (no schema changes)
- New harness integrations (Phase 6 still lives in chezmoi-config)
- Multi-user / auth / cloud sync (forever-deferred, see decisions.md)
- Backwards-compat shims for old URLs beyond simple redirects

## Information architecture

### The collapse

| current view | v0.2.0 fate | access |
|---|---|---|
| inbox | **Inbox** — primary, default | `g i` · `1` |
| overview | folded into Inbox metric strip | — |
| latest | gone (Inbox shows newest first) | — |
| projects | **Projects** | `g p` · `2` |
| archive | filter on Inbox | `g a` opens with filter applied |
| settings | modal overlay | `,s` (leader+s) |

Number keys `1` and `2` jump to Inbox and Projects. Digit keys `3-6` are
unbound at the top level (free for future use). The tabbar at the top
of the page shrinks accordingly.

### Settings as overlay, not view

Settings becomes a full-page modal opened via `,s` or `:settings`. Esc
or `,s` toggles it closed. Contains the four current sections (phone
notifications · notification destinations · theme · about). Tab-cycling
the in-app report tabs (`gt`/`gT`) is unaffected.

### Archive as filter, not view

Archived reports surface in Inbox only when the filter is active:
- `g a` — opens Inbox with archive filter on
- `:archive` — same
- Esc / `g i` returns to default Inbox

The titlebar shows `archive` in place of `inbox` when filtered. The
focused-row actions still work — `a` toggles unarchive, `dd` deletes.

## Operational metric strip

Sits between the titlebar and the view content. Renders inline; not
sticky on scroll. Each chip is clickable to filter the view below.

### Inbox strip

```
awaiting 4  ·  open asks 7  ·  in-flight 1  ·  today 12
```

- **awaiting** — reports with `status: awaiting-review` and not archived
- **open asks** — total unanswered interactive blocks across all reports
- **in-flight** — reports with `live.updated` within the live window (60s)
- **today** — reports `created` in the last 24h

Clicking a chip filters the inbox below. The active filter shows as a
pill next to the titlebar (`awaiting filter active · Esc to clear`).

### Projects strip

```
17 projects  ·  6 updated this week  ·  3 with open asks  ·  larkline (latest update)
```

- **N projects** — count of enabled (non-hidden) projects
- **updated this week** — projects with at least one report `created` in last 7d
- **with open asks** — projects with at least one unanswered interactive block
- **latest update** — project name of the most-recent report (links to it)

### Narrow viewport (< 720px)

Strip collapses to a single line, smaller font, no separators. The chips
remain but lose their secondary text.

### Empty / first-run state

When everything is zero, the strip says `nothing in flight · welcome` or
similar — keeps the layout stable but reads as friendly rather than dead.

## Keyboard model — vim-faithful, modal

### Modes

- **NORMAL** — default. Every binding live. Cursor follows focused row /
  section. Statusline shows `▌ NORMAL`.
- **INSERT** — active when focus is in a text input or textarea (the
  free-text response field, the add-destination form, etc.). All
  bindings disabled except `Esc`. Statusline shows `▌ INSERT`.

The vim-nav script already maintains this state for in-page scroll/find;
v0.2.0 elevates it to the whole app and removes the inconsistencies.

### Movement (NORMAL)

| key | action |
|---|---|
| `h` / `j` / `k` / `l` | left / down / up / right |
| `g g` | top of view |
| `G` | bottom of view |
| `[` / `]` | previous / next section |
| `Tab` / `Shift+Tab` | next / previous unanswered ask (in report) |

### View jumps

| key | action |
|---|---|
| `g i` | Inbox |
| `g p` | Projects |
| `g a` | Inbox + archive filter |
| `g t` | next in-app tab |
| `g T` | previous in-app tab |
| `1` – `9` | switch to in-app tab N (Chrome-style, no modifier) |

**Digit binding is view-scoped:** on the dashboard (Inbox / Projects),
`1`–`9` switch in-app tabs. Inside a report, `1`–`9` pick the focused
ask's options (unchanged). The vim-nav mode dispatcher already
distinguishes context, so no key conflict.

### Actions on the focused inbox row

| key | action |
|---|---|
| `Enter` or `o` | open the report |
| `a` | archive (toggle — in archive filter, unarchive) |
| `x` | close (mark done) |
| `d d` | delete (with native confirm) |

### Inside a report (unchanged + extensions)

| key | action |
|---|---|
| `1` – `9` | pick option N for the focused ask |
| `y` / `n` | yes / no on the focused ask |
| `i` | focus text input on the focused ask |
| `Tab` / `Shift+Tab` | next / previous unanswered ask |
| `Esc` | defocus current input |
| `q` | back to Inbox |

### Leader (`Space`)

The leader prefix opens a one-letter menu for cross-cutting actions
that don't fit elsewhere:

| key | action |
|---|---|
| `Space s` | open settings overlay |
| `Space t` | cycle theme (system → dark → light) |
| `Space ?` | open the cheat sheet for the current view |
| `Space .` | repeat last action |

**Space-leader implementation note:** browsers map `Space` to
page-down scroll by default. The vim-nav mode dispatcher
`preventDefault`s `Space` while in NORMAL mode and treats it as
leader; native scroll lives on `Ctrl+f` / `Ctrl+b` for users who
want it. In INSERT mode (text field focused), Space behaves
normally so typing isn't broken.

### Command palette (`:`)

Open with `:`. Type a command name (autocomplete via Tab — already
wired). Commands map 1:1 to the bindings above, plus:

- `:archive` — filter to archived reports
- `:settings` — open settings overlay
- `:cheat` — open the full reference (not the contextual `?`)
- `:filter <kind|project|status>` — narrow the inbox

### Cross-app shortcuts

| key | action |
|---|---|
| `/` | in-page search (current scope) |
| `⌘K` / `Ctrl+K` | cross-report search palette |
| `?` | help overlay for the current view |

### Help system

`?` opens a translucent full-page overlay showing the bindings relevant
to the current view. Inbox shows row actions + view jumps + leader.
Report shows ask shortcuts + section nav + leader. Projects shows
panel nav + per-project actions.

`:cheat` opens the full reference (every binding, every view). Same
overlay, just no view filter. Both close on Esc.

### Mode indicator

Statusline shows `▌ NORMAL` / `▌ INSERT`. Already implemented for the
vim-nav script's own state — extend the same state machine to cover
input focus changes triggered by any element, not just on-page inputs.

## Visual: inbox cursor

The focused-row state needs visible affordance distinct from hover:

- **Hover** — current behavior (background tint) — mouse-driven, ephemeral.
- **Focused** — left-border accent (`var(--tn-blue)`, 2px) + slightly
  brighter background. Persists between j/k presses. One row at a time.

Scroll-into-view happens automatically when j/k move the cursor below
the viewport.

## Migration

### URL redirects

- `/?v=overview` → `/` (Inbox)
- `/?v=latest` → `/` (Inbox)
- `/?v=archive` → `/?archive=1`
- `/?v=settings` → `/?settings=1` (opens overlay on load)

These are query-string only — no server-side redirects needed.

### Removed bindings

The view-jump digits (`1`–`6` switching between inbox/overview/latest/
projects/settings/archive) are gone. `1`–`9` now mean tab-switching
on the dashboard. View jumps move under `g i` / `g p` / `g a`.

### Removed UI

- The tabbar's `view-tabs` becomes the two-tab strip. Width recovered
  goes to the metric strip and a centered titlebar.
- The "tracked projects" toggle panel inside Projects view stays —
  unchanged behavior.

## Build sequence

Three commits, three rcs, one tag.

### Phase 1 — Keyboard core (rc1)

- Focus model on inbox rows; `j` / `k` cursor; `Enter` / `o` opens.
- Row actions: `a` (archive toggle), `x` (close), `d d` (delete).
- Mode indicator: NORMAL / INSERT in statusline reflects input focus.
- Scroll-into-view discipline.
- Tag: `v0.1.24-rc1`. Old views still present.

### Phase 2 — IA collapse + metric strips (rc2)

- Drop overview / latest / archive tabs from the bar.
- Build operational metric strip at top of Inbox + Projects.
- Settings becomes an overlay (`,s`).
- Archive becomes a filter (`g a` / `:archive`).
- Query-string redirects for old URLs.
- Tag: `v0.1.24-rc2`.

### Phase 3 — Help + g-prefix + polish (final)

- Context-aware `?` overlay per view.
- `g g` / `G` / `g i` / `g p` / `g a` / `g t` / `g T`.
- Leader (`,`) menu: `,s` / `,t` / `,?` / `,.`.
- Command palette refresh — autocomplete sees the new command set.
- Cheat-sheet (`:cheat`) — full reference.
- CHANGELOG entry, README screenshot refresh.
- Tag: `v0.2.0`.

## Decisions log (locked)

These were open during draft; locked in 2026-05-27. Listed so a future
reader sees the chosen-and-why, not just the chosen.

1. **Leader = `Space`.** vim-nav preventDefaults Space in NORMAL mode;
   native page-down lives on `Ctrl+f`/`Ctrl+b`. INSERT mode passes
   Space through. Comma was rejected — muscle-memory cost too high vs.
   the universal-modern Space-leader idiom.
2. **`1`–`9` = in-app tab switching** (not view jumps). View jumps are
   `g i` / `g p` / `g a`. Matches Chrome / browser tab convention;
   leaves the digit row consistent with how power users hold tabs in
   their head.
3. **`d d` for delete** — vim double-tap with native confirm. Adds a
   small key-buffer timer (500ms) but no other state. `D` (capital)
   was a tempting shorter form but reserves the upper-case row for
   future things (`D` could later mean "duplicate", etc.).
4. **Cursor persistence: yes.** Opening a report and returning
   restores the focused inbox row by report id (not by position — so
   if you archived something, the cursor stays on the right report).
5. **Project reorder gets `J` / `K` in the tracked-projects panel.**
   Capital J/K shifts the focused project down/up. Cheap to add, and
   without it the panel is one of two mouse-only surfaces left.
6. **`:filter` is single-keyword.** `:filter audit` (kind) /
   `:filter acme` (project) / `:filter awaiting-review` (status). The
   palette autocomplete shows what namespace a token resolves to.
   `kind=audit` syntax was rejected — lighter to type, the autocomplete
   pre-disambiguates anyway.

## Success criteria

We know v0.2.0 landed when:

- You can do a full triage session (open dashboard → handle every
  inbox item → archive resolved ones → close session) without touching
  the mouse.
- The cheat sheet (`?` overlay) is sufficient — you don't have to
  re-read this spec to remember bindings.
- The metric strip answers "what's going on?" without scrolling.
- The two-tab IA holds up; no one says "where do I find X?" about a
  surface you used to find in `latest` or `overview`.

## Not promises

The numbers in the metric strips (4 / 7 / 1 / 12 / 17 / 6 / 3) in this
spec are placeholders. The chip wording can change as we build it.
Same for the leader-menu commands — we'll refine as the muscle memory
forms.
